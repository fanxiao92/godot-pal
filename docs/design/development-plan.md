# 开发计划

## 原则:垂直切片优先

整个游戏太大,不可能一次写完。开发顺序遵循**垂直切片优先**:先用很小的范围把"资源转换 → 加载 → 渲染 → 玩法"整条链路打通,证明架构可行,再横向铺开补全部内容。

`pal-extract` 工具也增量做:先只提取垂直切片需要的那点资源,后面再补全所有 MKF 格式。

## 里程碑

### M0 · 项目骨架与工具链

状态：已完成。实施范围见 [M0 计划](../milestones/m0/plan.md)，当前环境与命令见 [根目录 README](../../README.md)。以下保留里程碑目标；实际采用 xUnit + 进程级 smoke test，GdUnit4Net 后于 M2 的 #12 关卡通过后接入，不能倒写为 M0 当时已使用。

- 使用 Godot .NET 建立 C# 桌面游戏项目,确定 Godot/.NET 版本并验证 CLI 构建。
- 确认并配置 GdUnit4Net 及核心层纯 .NET 测试方案。基本 CI(构建 + 测试)。
- 仓库目录结构、README。

### M1 · 场景资源提取
- 核对真实数据与 sdlpal 的 Win95/98 分支,实现 MKF 读取及当前场景需要的解压能力。
- 只提取 1 张地图、瓦片、相关精灵、调色板及场景对象初始数据,产出 PNG + JSON。实施范围见 [M1 计划](../milestones/m1/plan.md)。
- 保留原始 ID、坐标、显隐状态和脚本入口数值;不执行脚本,不将事件文件作为资源包依赖。
- 不包含事件转写、对话、语言包或字库,不以完整脚本资源闭包阻塞静态场景提取。

### M2 · Godot 场景构建与探索

状态：**已完成（2026-10-22）。** Windows 探索功能、自动/人工验收及收尾文档独立双轴终审已接受，成果已合入并推送 main；[#17](https://github.com/fanxiao92/godot-pal/issues/17)、父规格 [#11](https://github.com/fanxiao92/godot-pal/issues/11) 及后续跨盘测试缺陷 [#19](https://github.com/fanxiao92/godot-pal/issues/19) 均已关闭，远端完整 Windows headless CI 已通过。实际入口、独立配置及任务状态见 [M2 计划](../milestones/m2/plan.md)，分层证据与限制见 [验收记录](../milestones/m2/acceptance.md)。

- 显式校验 M1 PNG/JSON 输入包并导入为 Godot 原生 Resource/PackedScene/Texture2D；独立 `.tres` 探索 profile 另行配置起点及经离线核对的默认领队行走参数，Prepare 不 author profile，运行时不读取 M1 JSON/MKF、不修改既有 M1 包。
- 直接进入场景 2 / 地图 12，显示地图、对象与单领队，核对瓦片、遮挡和领队行走帧；多队员跟随不在本轮范围。
- 场景系统按参考实现离散行走、转向、地图与对象碰撞、相机；320×200 原始比例整数缩放，方向键/WASD，不加视觉插值。M2 曾交付的失焦暂停/清键扩展已由 #21 取消当前实现。
- 场景对象保持原始初始数据，不执行进入、交互或自动脚本，不自行循环对象帧或推进计时状态；动态行为留到 M3。
- #12 有界 GdUnit4Net 隔离兼容性关卡已通过并接入，#18 后续批准的固定源码包已交付；Core 继续原 xUnit 基线。M2 验收 Windows 开发运行，不包含导出包或其他平台验收；远端 Game headless CI 已随 #19 修复验证通过，使用人工资源而非原版数据。
- **目标:打通“资源转换 → Godot 加载 → 场景显示与行走”,不要求剧情或对话可运行。** 初始场景构建不等于原版某个剧情时刻的完整还原。

### M3 · 事件与对话垂直切片

状态：**已批准并本地集成至 `dab79ad8`；原自动门PASS、用户人工确认通过，当前CI待验证**。双轴复核已关闭原六项source finding，精确 `5bf481f`同tree匹配双语GPU各10零差/2calls；精确 `dab79ad8` 原完整共享门经独立证据复核支持。本对话用户确认 Windows 完整人工清单通过（含两语言/物理输入/Alt-Tab/缩放关闭），非agent独立实测。规格外 Observer 已停用，历史工具P1和 verifier not-satisfied 保留但非 M3 功能门，不宣称修复或隐私风险消除；当前integration人工资源Windows CI待验证，#20整体收尾及发布回填仍待结果/权限。具体范围见 [M3 计划](../milestones/m3/plan.md)，证据与待门项见 [分层检查点](../milestones/m3/acceptance.md)。M2 完成不自动证明 M3 验收。

- 已接通独立 scene4/map10/owner60 的“完整事件转换 → 搜索 → trigger → 双语对话 → 返回探索/再次交谈”；不绑定 M2 场景2，不改原始对象/脚本。
- 完整 faithful 集合保存与重建、具名字段重新编码及严格加载验证已实现；运行时仅支持切片所需 setDialog/showDialog/end，raw 或其他未支持闭包明确拒绝。全量 opcode、auto、条件/调用及正常场景调度不在此切片。
- 已接入显式准备的原生语言/画像/提示/字形资源，默认简中、启动时可选英文，保留原始消息引用；对话提示 F9–FE 轮转/恢复不是 M7 通用水火动画。
- 共享探索已按参考取消额外失焦冻结/清键/fresh-press，保留100ms离散行走/晚到不补走；逻辑输入不证明物理键盘/OS焦点交付。
- **目标仍是一个真实事件闭环，不是场景4正常自由探索或完整原版剧情。** 本地组件/headless/GPU、已完成原共享门、用户Windows人工反馈与当前远端人工资源CI待验证分层记录；Observer历史缺陷独立保留，自动门PASS不外推整体验收，后续doc提交不冒称已跑CPU/GPU。

### M4 · 战斗垂直切片
- 事件能触发一场战斗。
- 最小回合制战斗:普通攻击、回合顺序、胜负判定、经验。
- 战斗 UI 最小版。

### M5 · 数据与脚本全量转换
- `pal-extract` 覆盖所有 MKF 格式。
- 完成原版字节码 → 忠实低层 `events.json` 的全量转写、opcode 注册表和反向编译器,对完整脚本 chunk 逐字节往返验证;不恢复结构化控制流。
- 提取全部场景 / 物品 / 法术 / 怪物数据。

### M6 · 系统补全
- 完整战斗:五行相克、法术、战斗道具、敌方 AI、逃跑、奖励结算。
- 菜单系统全套:背包、法术、装备、状态、商店。
- 存档 / 读档(GameState JSON,通过 Godot FileAccess 写入 / 读取 `user://` 本地文件)。

### M7 · 体验补全
- 音频:预转换的音乐 / 音效 / 语音接入。
- 确认目标 Godot 版本支持的视频格式与播放方案,将 AVI 过场离线转换后接入(内置播放方案优先评估 Ogg Theora `.ogv`,不预设 MP4 / WebM 可直接播放)。
- 转场特效、调色板循环动画(水 / 火)。
- 结局流程。

### M8 · 通关验证与打磨
- 从头到尾能通关。
- 对照原版 / sdlpal 校验忠实度(数值、剧情、触发)。
- 打磨手感、性能。

## 第二阶段(本次范围之外)

忠实移植完成后,才考虑扩展能力:手写新内容的结构化事件子集、现代脚本 API、内容编辑器、新场景 / 剧情 / 玩法等。架构已为此留好空间,但不在当前计划内;结构化命令不能提前视为原版转换器或运行时已支持的功能。

## 实现细节备注

- **音频格式转换**:RIX 是 OPL FM 合成格式,ffmpeg 不直接认 —— 中间需要一个 OPL 渲染器先把 RIX 转成 wav,再转 ogg。属实现细节,到 M7 再处理。
- 每个里程碑进入实现前,在 `docs/milestones/<里程碑>/plan.md` 编写实现计划,再编码。任务规格和实施结果记录在 GitHub Issues,检查由测试与 CI 执行;仅对值得长期保留的特殊调查另写记录。
