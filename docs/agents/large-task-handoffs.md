# 多票协调与恢复

仅协调多个 ticket 或恢复协调会话时读取；单票实施不默认读取。本页只处理跨票推进、集成身份、执行权和交接，单票的目标、影响预算与验收条件以其 Issue 为准。授权与全局执行边界见根目录 [AGENTS.md](../../AGENTS.md)。

## 推进下一票

1. 按 [Issue 工作流](issue-tracker.md)读取实时正文、评论、子票及直接依赖，区分父规格与实施叶子。父规格用于覆盖与阶段判定，实际执行选择目标和验收已明确的小票。
2. 核对前置票的验收收据及实际集成位置，再确定本票使用的 integration tip。Issue 关闭、隔离树中已有实现和实现已进入本票基线是不同事实；只推进前置已满足且获准的票。
3. 新票使用 fresh session，携带实际 base/cwd、HEAD/dirty 身份、允许范围、已确定的跨票接口和可复用收据。文件预算按票累计，以规格为准，不按执行片或 commit 重置；历史过程留在原件中。
4. 开始前核实唯一 writer、活动执行及所需引擎执行权。委派、提交、集成、远端操作和清理按各自授权执行，单票完成不自动授予下一票执行权。

## 最小当前状态

复用现有执行记录，保留一个权威当前状态；GitHub 仍是规格与任务系统。

| 内容 | 必须可定位的事实 |
|---|---|
| 范围 | 阶段目标、约束、已授权及待授权动作 |
| 任务图 | 已发布/待细化票、依赖、当前票、下一动作及原因 |
| 源码 | 实际 integration tip、当前候选、工作区与 HEAD/dirty 身份、未闭合接口契约 |
| 执行权 | 唯一 writer、活动 run/attempt、执行额度与期限、待决请求及归还状态 |
| 证据 | 已验收能力及对应版本/检查层/收据；失败、未执行项及已发生副作用 |

已完成票只保留能力和证据索引，局部实现、完整日志及逐次 RED/GREEN 留在原件。遇到接口冲突、失败或身份不匹配时再定点读取。采用文件化 current 时，结构及安全替换约定见[当前状态校验](../testing/agent-evidence.md)；校验结果不替代 Git、Issue 或调度器事实，也不授予执行权。

## 收票与阶段判定

- 收票先读结果、候选身份、行为/公共契约差异、实际验证、未完成项和待决问题，再按验收范围核对 diff、必读评审报告及原始证据；短交接不替代独立评审。
- 验收绑定实际候选及检查范围。仅在源码和适用条件未变时复用已有收据；集成后另核跨票接口和受影响链路，不将实施者自述或旧版本结果转签为当前通过。
- 分别记录工程前置、规则能力、正式接线和阶段交付。首批小票完成不等于父规格完成；阶段收尾核对全部批准范围、未发布或未闭合能力、必要验收及剩余限制。

## 切换与恢复协调会话

1. 切换前确认活动任务已交接、待决请求已处理、writer/执行租约已归还；记录尚未明确的写入或远端副作用。
2. 保存最小当前状态、未提交改动及下一动作，历史原件保留。需要精简导出、源码快照或派发预检时再用[运行工具入口](runtime-workflow.md)，不默认增加工具检查或生成另一套交接脚本。
3. 新会话先核实际调度器及既有执行记录、Git/dirty 身份、当前状态版本和有效授权；写操作响应不明时先只读核实副作用。当前文件中的 idle 或工具校验通过不证明实际执行已结束。
4. 从已核验的当前状态继续；结束的 run 留在历史/lastAttempt，旧任务书和失败尝试不恢复已归还或取消的权限。已接受的检查保留原身份，失败的完整门不通过拼接旧结果续成成功。

测试失败分类、停止及再次运行条件统一见[测试异常处理规则](test-diagnostics.md)；其它工具失败与未知写入按根规范核实后处理。本页不另设纠正次数、重试额度或默认 checkpoint 提交规则。
