# 测试异常处理规则

本页是当前测试异常处理入口。当前任务必须按实时 Issue、实际提交、`./pal.ps1` 及原始证据重新判定，不沿用过时历史结论。

## 处理顺序

1. 运行前按[验证矩阵](../testing/verification-matrix.md)选择档位与测试层，核对当前分支/HEAD、前门命令、runsettings、工具链配置和产物输出目录。实际 Godot/GdUnit/Prepare 执行在本地全局串行；未知进程只取 PID/Name，确认归属前暂停。
2. 保留原始命令、cwd、提交/dirty 范围、数字退出、原始输出、本轮 TRX 与 `run-summary.json`。结果同时核对进程退出码与 TRX `outcome`/`failed`；报告工具或外层代理退出不能覆盖测试进程的原结果。
3. 分类而非猜因：功能断言失败、活性问题、会话中止/崩溃、未知退出、输出不完整、资源/Prepare 失败、采证失败分别记录。部分 Passed、`aborted=0`、单条 PASS 或报告 exit0 都不能表示完整通过。
4. 已观察到目标更新但状态错误，按功能失败处理；期限内未观察到必要更新，按未完成/活性问题处理。不得用外部墙钟、协程恢复或后续状态把两类合并。
5. 中止、崩溃、超时、未知退出、损坏/缺失结果立即保留现场并停止。正常且完整的非指定编译/功能失败，先只读定位，再按[单任务有界纠正](task-execution.md)核对原契约、权限及剩余额度；门内不自动重试，不设 quarantine 清单。禁止拼接旧 TRX、提高时限、放宽断言、停用捕获或升级工具链来取得通过；硬停止后的新运行仍须明确授权。

## 时序与变异触发

当任务改动时序、Game 迁移、调度偶发、输出捕获或断言时：Core 通过公开构造/输入/显式时间验证 deadline 前、截止时、晚到不补步、回绕和重新调度；Game 通过真实输入交付及已核实的 `UpdateCompleted` 等生产完成边界验证引擎接线。二者证据互补，集成等待不能替代 Core 精确时间，Core 通过也不能证明信号/资源/场景连接。

保留有界等待作为防挂起保护，并把同一单调时钟与帧身份只记录在必要的输入交付、更新进入/完成和状态观测边界。变异逐例运行、逐例恢复；核源码及实际运行目录的 DLL/PDB，必要时显式 Rebuild。只有指定功能断言失败才算捕获目标错误；编译失败、缺资源、崩溃或超时不算反例通过。

## 工具链与证据边界

工具链版本与包配置以 [Pal.Game.Tests.csproj](../../tests/Pal.Game.Tests/Pal.Game.Tests.csproj)、`global.json` 及仓库配置为准（决策见 [ADR-0006](../adr/0006-split-game-tests-and-official-gdunit.md)）。排查 Game 挂死或崩溃时使用 `./pal.ps1 test game --blame-hang`（CI `ci game` 默认开启 `--blame-hang-timeout 2m`）。

本页不创建第二诊断框架，不把 Unit、headless、GPU、人工桌面与远端 CI 相互替代。任务状态、Issue 评论和远端 CI 是动态事实，不能从历史标题或旧计划页推断。
