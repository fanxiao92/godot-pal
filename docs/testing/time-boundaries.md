# 时序与外部调度延迟

修改业务时间、输入更新边界或相关断言，以及 Game 迁移、调度偶发诊断时，先读本页。这里是从根规则移出的完整时序契约；普通选层只需[测试职责矩阵](test-layers.md)，历史症状按[当前诊断规则](../agents/test-diagnostics.md)的明确触发进入。

- **分层验证**：Core 单元测试验证业务时间边界；Godot 集成测试验证真实输入、信号与更新的连接及顺序。功能断言依据业务状态和实际处理边界，不以测试端观测耗时替代“下一次更新”等契约。明确的性能指标另设性能测试，说明测量起止点与环境。
- **确定性时间**：通过现有公开接口显式传入时间值，覆盖截止前、截止时、晚到更新及调度重置；例如首步立即、后续按节拍、晚到不补走。使用真实业务实现，不依赖 Sleep、私有状态修改或替代生产逻辑证明规则。
- **实际更新边界**：集成测试从输入被处理起，到对应实际更新完成后核验该次状态快照。使用前查证引擎信号与目标回调的执行顺序；注入时间、局部等待帧计数、日志排列和测试协程恢复时间均不能直接当作目标回调已执行的证据。
- **证据互补**：外部延迟可能使正确实现与错误冷却实现都在首次实际更新时满足截止条件；集成测试通过不能替代确定性时间边界测试。修改时序断言时，用针对性反例或受控变异证明它仍能捕获目标错误，而非仅放宽阈值。
- **超时分类**：保留有界等待作为防挂起保护。已观察到有效更新但状态错误，报告功能断言失败；期限内未观察到必要事件或更新，报告未完成或活性问题，保留诊断证据，不直接归因于业务冷却。两者均不得计为通过。
- **定点诊断**：时序含糊时，仅在必要的输入交付、更新进入／完成和状态观测边界记录同一单调时钟及帧身份，优先缓冲后统一输出，减少探针干扰。临时探针在交付前移除；一次通过不足以证明偶发问题已修复，不以反复重跑获取通过代替诊断。
