# Unit 默认反馈信任原生工具，不重复构建审计框架

2026-11-02，用户在 #69 执行复盘中批准方案 B：日常 Unit 与 Unit CI 采用直接 `dotnet test`、原生 runsettings、最少 checkout/报告存在性检查及 Actions 日志/artifact。SDK 政策由 `global.json` 与 dotnet 解析，零执行和 skip 由既有 VSTest/xUnit 配置拒绝；不把临时 Python 核验器、自定义进程执行器或候选 JSON 协议变成默认依赖。

这是对 #69 原证据/成本契约的后续调整，不改写已关闭规格、原验收或失败原件。拒绝“保留全部审计要求，再加固所有辅助工具”的方案，因为重复实现已造成 SDK/LFS/事件归属等误判和恢复成本。默认路径接受不再提供全仓散列、TRX 完整身份图/RunInfo 独立审计、实时 API 双重证明、自有 root/双流 EOF 和精确 Stopwatch 成本保证；明显失败、中止/未知退出、零执行、skip 或缺报告仍不能通过。

强审计工具、完整门及其严格接口继续保留，仅按明确需求选择，不删除或以普通反馈替代其保证。Unit-only 的业务覆盖损失与重型恢复条件仍见 [ADR-0002](0002-unit-only-first-stage.md)。本决定不升级依赖、不修改服务端保护、不授权提交/推送；本地实现与远端实际生效分别核对。
