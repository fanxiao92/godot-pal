# 数据层与脚本层分层转写

原版内容由两层构成：**数据表**（怪物、法术、物品、场景对象、角色基表等静态内容，回答“世界内容是什么”）与**脚本指令**（SSS.MKF chunk 4 指令与各入口，定义逻辑与剧情，回答“逻辑怎么走”）。两者关系是脚本操作数中的 ID 引用数据表记录（例如 `giveItem.itemId` 指向对象表中的物品）。

已确认采用两套契约分别转写：

- **data-schema**：数据表只读提取 + 严格校验 + 语义解析（字段值与来源散列/长度核对），不重编码回原始字节，不提供 rebuild 命令。
- **events-schema**：脚本忠实转写 + opcode 注册表 + 反向编码，逐字节往返验证。

代价是维护两套契约与共享的引用命名约定（`itemId`/`magicId`/`enemyId` 等），但换来每层各自清晰的验收边界：脚本以 byte-exact 往返证明表示无损，数据以字段独立核对证明语义正确；两者都不被强行套用对方的验证方式。运行时消费现代资源、不回读原始归档的既有边界不变。
