## 1. 目标与已确认范围

打通“**M1 资源包 → Godot 加载 → 场景显示 → 单领队探索**”。启动后直接进入场景 2 / 地图 12 的探索验证入口，不做标题菜单或场景选择器。

- 使用 M1 的地图、瓦片、调色板、精灵和场景对象初始数据，验证显示、透明、遮挡以及领队行走帧。
- 实现单领队的行走、转向、地图与对象碰撞、相机和键盘输入。
- 采用独立探索测试配置补足起点及所需角色参数，不修改既有 M1 包、不通过改变对象状态制造展示。
- 验收 Windows 上由 Godot 启动的桌面开发运行；跨平台仍是目标，但其他系统和导出包另行验证。

**不包含**：多队员或特殊 follower 跟随、事件转写与执行、进入/交互/自动脚本、对话、语言包、字库、NPC 脚本行为、音视频、转场、调色板循环、菜单、存档、导出包及其他平台验收。不为此切片预造完整事件总线、战斗状态机或通用内容系统。

这不是原版开场，也不是某个剧情时刻的完整还原。单领队与静态对象是 M2 的阶段范围，不是最终游戏的行为简化；动态状态、资源依赖和对象行为从 M3 接入。

立项时只有启动文字、核心标记和 640×400 viewport；这些是历史起点。当前已交付 Core 探索状态/规则、原生场景加载与绘制、320×200 逻辑视口、输入/焦点和相应测试。以下参考定位仍用于核对行为，不是要求重新实施。

| 主题 | 实施时定向读取的参考 |

| 地图与精灵遮挡 | `scene.c` 的 `PAL_MakeScene` / 精灵与覆盖瓦片列表构建、排序、重绘，`map.c` 的瓦片定位与高度 |

## 3. 资源准备与测试配置

### 3.1 显式准备、游戏只读加载

1. 输入是用户选定的完整 M1 包；根相对引用、manifest v1 与散列规则沿用既有契约。初始真实验收采用已验证的 scene2 / map12 / palette0/day；这只是显式参数，不代表进入脚本选择的调色板。
2. 已交付显式 PowerShell 入口 `scripts/Prepare-GameScene.ps1`：校验完整包，再生成 `Assets` 下的 Godot 原生场景、Resource 和 PNG 纹理，不把 M1 JSON 原样复制为运行依赖。实际参数与定位见下节及 [README](../../../README.md#m2-原生资源与普通-main)。已有经核对的真实资源直接复用，不建议为文档同步再次导入。
3. 准备时校验版本、清单、产物长度/散列、资源引用与 ID 一致性，保持包内路径相对资源包根；不将子目录 JSON 的引用误解为相对其自身目录。
4. 准备步骤不读取原始归档、不执行提取、不修改原包，也不默认清空或覆盖有内容的目标目录。拒绝越出包根的引用和危险的源/目标路径关系，不因准备失败宣称资源可用。
5. 游戏通过 `ResourceLoader` / `PackedScene` / `Texture2D` 加载原生资源与独立 typed profile，不解释 M1 JSON/manifest；启动不自动提取、准备或复制，不依赖开发机外部绝对路径，不引用 `Pal.Extract` 或解析 MKF。装载时仍检查必要结构、版本与引用，缺失/损坏资源明确失败，不静默补图或猜值。
6. 原始资源、复制资源和引擎生成缓存保持 Git 忽略；小型人工测试资源可以提交，但不能夹带原版内容。

### 3.2 独立探索测试配置

M1 包没有队伍坐标、朝向、层值或相机初值。参考默认新游戏从场景 1 开始并运行进入脚本，不能据此声称已有场景 2 的原版出生点。

- 在包外独立配置测试入口，明确选定资源包/场景、默认 role0、世界起点、朝向、初始层值及帧相位初始化。相机由起点和参考屏幕锚点推导，不与世界坐标另存互相矛盾的真值。
- 起点需以地图和初始对象碰撞验证可站立、可行走；具体坐标是实施时查证结果，不要求用户手选，也不执行 `0x0DD9` 等进入脚本寻找或制造状态。
- 默认领队精灵来自包内 `defaultParty`，不把其他角色精灵当作当前队伍，不在代码散落硬编码内容。
- **角色行走参数是已确认的补充配置**：离线只读核对 DATA chunk3 的 `PLAYERROLES.rgwWalkFrames`，记录字段值和可追溯来源（归档身份、chunk/字段位置、role ID），作为本轮单领队配置输入。运行时只读该现代配置，不能凭 MGO 总帧数猜测参数，也不能回头读取 MKF。
- 此次离线核对不扩展 M1 导出命令或修改既有包；如后续完整角色数据已正式导出，再替换这一有限测试配置，不把它扩张为手工维护的完整角色数据库。
- #14 已交付并验证：真实测试起点 `(736,688)`、南0、Layer0、StepPhase0；相机由 `(160,112)` 屏幕锚点推导为 `(576,576)`。role0 的 `WalkFramesWord=0` 来自 DATA chunk3、字节偏移768 的 `rgwWalkFrames`，按参考非4分支解释，不表示没有行走帧。完整归档散列与包身份保存在本机独立 profile；不在文档复制原始数据或把此值推广到其他数据集。
- 当前配置采用下节 Godot 原生 Resource 类型与字段；旧 JSON 表达已替代。未知参数不能以未验证的默认值掩盖。

### 3.3 已交付的原生入口与配置

- 准备入口：`scripts/Prepare-GameScene.ps1`，必需 `-InputPath <完整M1包>` 与 `-OutputPath <Assets内新或空目录>`，可选 `-GodotPath <exe>`（否则 `GODOT_BIN`，再查 `godot`）、`-TimeoutSeconds <1..600>`（默认60）。退出码成功0、参数错误2、数据/导入错误1；没有覆盖开关。
- 输入必须在 `src/Pal.Game` 工程外；输出仅允许 `src/Pal.Game/Assets` 或其子目录，拒绝非空、双向重叠及链接/reparse 风险。脚本会构建 Game、准备纹理、执行 Godot editor import，再保存原生引用；失败可能留下不完整输出，不自动清理或回滚。命令示例见 [README](../../../README.md#m2-原生资源与普通-main)。
- 默认资源根为 `res://Assets`，场景为 `<资源根>/Scenes/Scene.tscn`；按 Maps/Tiles/Sprites/Scenes/Palettes 分类，来源元数据保留为原生字段。游戏用 `--m2-resources <规范化res://Assets或子目录URI>` 选择已导入根。
- 默认独立配置为 `res://Assets/Profiles/Exploration.tres`，游戏用 `--m2-profile <规范化res://项目资源URI>` 选择。改变资源根不会自动重定位配置；参数放在 Godot 的 `--` 之后，各只允许一次，未知/重复参数明确失败。默认资源和 profile 任一缺失都不能启动成功。
- **Prepare 只生成原生 scene/resources，不 author profile。** #14 另行离线核对并落地了默认真实 profile；T2 的地图静态视点已由 T3 领队起点替代，不保留第二套相机真值。真实原生资源、派生配置及缓存均受 Git 忽略，人工测试资源可提交。

profile 是 `PalExplorationProfile : Resource`，字段使用实际 C# 导出属性的 PascalCase，见 [类型定义](../../../src/Pal.Game/Scripts/Resources/PalExplorationProfile.cs)及 [加载校验](../../../src/Pal.Game/Scripts/Profiles/NativeExplorationProfile.cs)：

| 类型 / 字段 | 当前契约 |
|---|---|
| `PalExplorationProfile.FormatVersion` | `int`，必须为1 |
| `SceneId` / `BundleSha256` | `int` 场景号 / `string` 64位小写十六进制散列，与所选原生 `PalSceneData` 一致；真实切片为 scene2 |
| `Start` | `PalExplorationStart`，显式 `int X/Y`（SHORT或原始WORD表达）、`Direction`（南0/西1/北2/东3）、`Layer`（0..65535）、`StepPhase`（0..3）；坐标须不阻挡且至少有一个合法邻点 |
| `Leader` | `PalExplorationLeader`，显式 `int RoleId=0`、`int WalkFramesWord`（原始WORD，0..65535）、`PalWalkFramesSource WalkFramesSource`；精灵取原生 scene 的 defaultParty role0，不另存冲突精灵ID |
| `PalWalkFramesSource` | `string Archive="data.mkf"`、`string Sha256`（完整归档散列，与 scene 的 ArchiveSources 匹配）、`int Chunk=3`、`int ByteOffset=768`、`int RoleId=0`、`string Field="rgwWalkFrames"` |

清洁检出首次使用时，先完成批准的 bootstrap/build 与显式资源准备，再在 Godot .NET Editor 中创建已声明的 `PalExplorationProfile` 资源，赋予 `PalExplorationStart`、`PalExplorationLeader` 和 `PalWalkFramesSource` 子资源并逐项填写上述字段。`BundleSha256` 取所选原生 Scene 数据；来源散列与行走参数使用独立离线核对结果，起点须另经碰撞验证。保存到默认 URI 或显式选择的项目 `.tres` URI 后才启动普通 Main。没有通用 profile 生成脚本，测试 fixture writer 不是制作真实配置的入口；未核对的数据应停止报告，不猜默认值。

保留原始行走参数而不是按总帧数推断；执行按参考分支解释并验证所需帧，不能因未知值而自行补图。身份核验只读现代来源记录，不授权游戏读取 MKF。准备和 profile authoring 是两个独立的显式步骤，不修改 M1 manifest 或产物散列。

## 4. 探索与显示行为

### 4.1 视口、输入、节拍与相机

- 逻辑视口 320×200，默认桌面窗口 1280×800（4×），保持 8:5 原始像素比例，清晰像素整数缩放，剩余窗口区域留黑边。不是 4:3 拉伸，也不因窗口变宽而额外显示地图。
- 方向键与 WASD 通过 InputMap 操作；down/S、left/A、up/W、right/D 对应参考南、西、北、东。世界步位移分别为 `(-16,+8)`、`(-16,-8)`、`(+16,-8)`、`(+16,+8)`，不是屏幕直线四向或双键合成新方向。
- 保留参考最近按下且仍按住的方向优先、释放后回退的语义；同方向别名键与 OS 重复按键不能造成额外移动或错误释放。具体别名组合补测试，不把引擎默认轴合成当作参考规则。
- 普通探索首步立即、后续每100ms推进；公开 `Update(uint ticksMilliseconds)` 保留 uint wrap 的截止比较（时间差小于2^31ms），晚到更新最多走一步并从本次时间重新调度，不补走。窗口刷新与逻辑步进分离，不因高刷新率多走步；不加连续位置插值或平滑相机跟随。
- 尝试移动先转向，再检查目标点。成功才移动并推进走路帧；受阻原地转身、使用站立帧，不沿墙滑动。
- 三/四帧角色的帧选择、停止后的步相位遵循参考；不简单持续播放一个走路动画或每次停步都清零相位。
- 普通行走的领队屏幕锚点为 `(160,112)`，相机视口与世界位移同步；不改成 `(160,100)` 居中或自由相机，也不额外添加改变参考可达范围的相机 clamp。
- **M2 历史交付行为（已由 #21 修正）**：当时窗口失焦会冻结探索、清空输入，恢复需 fresh press，且重置调度；这些是 M2 桌面扩展，不是 SDLPal 行为。当前代码取消该策略：Main 不订阅 Window 焦点信号，Core 探索推进不接受焦点状态。该历史记录保留，不代表当前行为。

### 4.2 地图、对象碰撞与遮挡

- 保留两层瓦片、原始网格、透明、帧尺寸和高度。`preview.png` 仅是离线地图预览，不用它代替地图与人物的完整渲染。
- 地图碰撞按参考的世界目标点到菱形格换算与阻挡位判断；越界、半行边界和等号条件必须有独立期望用例，不按 PNG alpha 或“存在上层瓦片”推断阻挡。
- 对象碰撞按当前场景对象的状态和加权距离规则判断。显示与碰撞分开：`sState>=2` 的对象是否阻挡不能依赖是否有精灵、是否画出来或消失时间；距离恰好位于边界的情况必须验证。
- 保留对象与队伍各自的绘制锚点/层偏移；按参考选择需覆盖精灵的两层瓦片，再形成稳定的绘制顺序。不能以简单世界 Y 排序或“所有上层瓦片永远压在人物上方”替代。
- 帧宽高、透明区域、层值、瓦片高度与相机偏移共同参与显示；生成可测试的绘制顺序计算，再交给 Godot 绘制。

### 4.3 场景对象保持初始值

对象坐标、朝向、当前帧、状态与消失时间保持导出的初值，不为了展示改状态。无精灵和隐藏对象保留。

不运行进入/交互/自动脚本，不循环多帧对象动画，不推进消失计时、离屏负状态恢复或参考主循环中的自动排挤。渲染对象不等于推进对象行为；M2 的帧动画重点是领队行走。原始脚本入口只保留为来源数值，不验证不存在的事件文件执行引用。

## 5. 实现职责

| 位置 | 本轮职责 |
|---|---|
| `Pal.Core` | 纯逻辑探索状态、步进、碰撞、朝向/行走帧、相机坐标关系及可测试的绘制排序计算；不碰 Godot、文件 I/O 或 MKF |
| `Pal.Game` | 原生 Resource/PackedScene/Texture2D 与 typed profile 加载、Godot 场景及绘制、输入、窗口焦点、视口缩放、向 Core 传入实际时间及错误反馈 |
| 资源准备脚本/工具 | 校验 M1 包并显式导入为原生资源，不 author profile；不承担游戏逻辑，不新增另一套原始资源解码器 |
| 测试 | 核心规则保留现有 xUnit；Godot 集成设施已通过兼容性关卡并接入；已有 CLI 回归与启动检查保留 |

以少量明确输入、推进和结果接口承载规则，调用方与测试走同一规则入口。已交付 `ExplorationInput` / `ExplorationSession` 公开推进与不可变状态/绘制计划；Godot 在外层消费计划。后续沿用现有能力，不为假设的扩展点增加抽象。

## 6. 首个前置任务：测试框架兼容性关卡

**已完成 #12**：有界 GdUnit4Net 隔离关卡已通过并接入正式工程，见[兼容性记录](framework-compatibility.md)；Core 未迁移。后续 #18 另获批准交付固定源码 API/adapter 包、完整门禁与同字节稳定发布，来源/版本/bootstrap 以[包说明](../../testing/gdunit-source-packages.md)为准。下面保留原关卡设计作为历史验收标准，不要求重新选型或重跑。
