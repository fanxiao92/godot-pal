## 1. 目标与批准边界

交付 Windows 开发运行下的一条完整链路：

**完整事件集合离线转写 → 显式准备现代资源 → 独立对话验收入口 → 真实搜索交互 → 原事件执行 → 头像和文字显示/等待 → 结束并返回探索 → 再次交谈。**

- 以普通 NPC 对话为中心，不绑定 M2 的场景 2，不以支持全部 event/opcode 为完成条件。
- SDLPal 固定源码是行为参考；先查证可确定的事实，不把参考已经规定的行为变成用户代选题。无法确定且影响正确性，或拟偏离参考时再提出具体取舍。
- 独立验收上下文使用真实地图、NPC 原始记录和完整原事件，不激活隐藏 NPC、不挪位置、不截取脚本中段、不静默忽略副作用。
- **它不是原版开场、剧情快照或场景 4 正常自由探索。** 其他场景行为不纳入该测试上下文，是明确批准的测试隔离，不是正式场景调度规则。
- 保留 M2 单领队、方向键/WASD、320×200 整数缩放、离散行走/碰撞/遮挡能力，除第 4 节已批准的焦点修正外不改变既有规则。

**不包含**：全量 opcode 执行、所有 auto 行为、完整场景进入/自由探索、长剧情、切场、战斗、商店、背包玩法、音频、存档、其他平台、导出包和手写内容的结构化事件 profile。不为未来系统预造通用引擎、完整 GameState 或命令总线框架。

## 3. 转换、资源与运行时边界

### 3.1 事件集合：完整保存，有限执行

- 遵守 `events-schema.md` v1 faithful 封套、引用、字段/范围、入口零值与控制流零地址的区别；首次输出即完整保留 chunk 4 全部地址、顺序后继、opcode 和三个操作数，不导出裁剪片段冒充 faithful 集合。
- 具名注册切片实际需要的 003C、FFFF、0000 及验证这些映射所需的基础能力；其余可保持 raw。已有契约中的其他基础映射不因本文列出三种 opcode 就变成已实现或可静默接受。
- 完整集合的无损重建必须覆盖具名字段重新编码和 raw 保留；验证长度、散列与逐字节一致。通过语义字段/保留字段/注释修改的反例，防止只复制 source 就宣称映射正确。
- 按现有契约枚举已核实的场景/场景对象入口；对象表 union 类型未确定时记录缺口，不伪造根。无法证明归属的指令可保守放 shared，不猜 raw 操作数中的地址，不声称全游戏可达性分析完成。
- 运行时在执行前校验集合完整性、版本、字段、引用及选定入口的保守能力闭包。未选定的归档命令可以保存；请求执行未支持入口/raw 必须定位文件、标签、原始地址并明确拒绝，不能静默跳过或借 source 执行原始 opcode。
- 完整字节保存/重建与本事件行为分别验收；前者不证明全部 opcode 语义或原始文本已忠实。

### 3.2 显式准备与资源保护

- 已有 map 12/M2 原生包不能替代 map 10；调查未找到现成 map 10 包。实施时在新/空目录显式准备 scene 4 静态包与原生资源，不覆盖既有 M1 包、M2 资源或 profile，不自动重新提取/同步。
- 复用现有 MKF/YJ2/图像/调色板能力；头像直接 RLE 与精灵帧表的差异按参考处理，新增必要复用点，不复制另一套解码器。
- 增量转换语言包、头像 59、DATA chunk 12 的对话提示图标及所需字形，记录消费来源/参数/散列。语言默认简中，中英文共享事件引用，切换启动配置不改变剧情或入口，不增加对话中途热切换。
- 当前 SLF 路径的参考默认字库为 Unifont，并使用 ISO 字形覆盖；目标字符已核对可索引。按实际参考保留字形位序、宽高、字距和阴影，不随意改用系统字体/平滑字体；不把简中字库替换当作默认优化。
- 对话等待中的提示图标与 F9～FE 调色板轮转/恢复是本次对话行为，不因水火调色板循环排在 M7 就省略。颜色变化对画面的实际影响按参考验证，不能仅转动一张近似图标冒充全局调色板效果。
- 场景继续使用显式准备的 Godot Resource/PackedScene/Texture2D；新增事件 JSON 与现代语言包按已批准事件设计加载，不授权回读 M1 JSON、MKF、SLF、M.MSG 或参考 C 头文件。字形须先转为现代资源，运行时不解析参考源码。
- 真实原始/派生资源与缓存不提交、不上传；CI 只消费小型人工资源。准备失败保留状态并报错，不自动覆盖、清理或回滚输出。

具体新增 CLI、资源封套和独立模式启动入口在对应任务中结合现有实现冻结、文档化并测试；本文不编造已存在的命令、资源类或路径。局部可逆且不改变行为的实现细节自行处理，公共兼容性或未批准的行为变化仍需上报。

## 4. 忠实执行与焦点修正

- `Pal.Core` 只负责可测试的命令/状态、可暂停执行与对话推进规则，公开传入时间/输入；Godot、文件 I/O、节点、纹理与真实输入留在外层。
- trigger 持续执行到真正等待边界，再由显示完成/玩家输入回执继续；不统一成每 tick 一条，不因异步接入而跳过等待或重复执行消息/结束副作用。
- 保留原始消息引用、SLF 区间匹配及区间结束后的执行位置；用独立人工数据覆盖不同翻译行数、区间内部入口、清屏、空行和切片涉及的文字控制语义。不能按翻译行数改写脚本。
- 普通对话阻塞原场景更新，与失焦不是同一原因；有些脚本等待会明确调用场景更新，不能统一冻结/后台推进全部脚本。切片未使用的更新型等待不能被标成已支持。
- 搜索走真实输入路径，按参考处理 NPC 转向、站立帧、caller、入口回写、结束后的 50ms 延迟与输入清理；不要混淆“交互结束清瞬时按键”和“失焦时强制清所有方向”。具体搜索键及翻页/加速判定按参考核对，不能默认 Godot ui_accept 就等价。

**已批准修正 M2 焦点扩展：**

- SDLPal 应用层没有桌面失焦即暂停业务/冻结计时的门禁；APP 后台事件的 `g_bRenderPaused` 仅控制渲染，不是业务暂停。
- 从共享探索链路取消失焦冻结、因焦点额外清方向、回焦等待 fresh press 及焦点驱动的调度重置；事件/逐字显示/限时等待不因失焦冻结时间。
- 不把“应用没有显式清键”误写为“旧按键必然继续保持”。参考通过 SDL 轮询键盘，Godot/OS 的释放与回焦交付须针对性查证和集成验证，不自行制造粘键，也不未经说明加入新规则。
- 不增加追帧/补走，不改既有正常探索 100ms 节拍、晚到最多一步和无插值；这些与额外的焦点暂停策略分开。
- 保留 M2 历史规格、验收及失败原件；修订当前决策和受影响测试，让新测试证明参考一致性，而非继续强制旧扩展。

## 5. 独立模式与失败边界

- 模式必须显式选择并标明用途，不悄悄把普通 M2 Main 变成场景 4 正常游戏。保留无 M3 资源时的既有场景入口与缺资源诊断，除批准的焦点行为外不破坏兼容性。
- 运行配置声明真实资源身份、选定 owner/入口、测试起点与调度范围；不能运行时通过隐藏状态修改关闭 owner 57 或其他对象。所有原始对象继续参与显示/碰撞，未选定行为不属于该测试调度上下文。
- 对未支持入口的显式请求失败；不把其他入口从测试调度中隔离当成它们执行成功。若后续希望开放正常场景循环，须另行核对活动 auto/触碰/出口闭包，不能沿用本模式声称支持。
- 缺语言包、缺消息、坏事件引用、非法字体/画像、资源身份不符和不支持命令均明确报错，不能替代文字、混用另一语言或显示半个场景却标记成功。

## 6. 分层验收标准

1. **离线转换**：人工全数组及当前真实 chunk 的完整保存/重建；含下标 0、raw、未用非零操作数、跨文件引用、顺序后继和字段重编码反例；原始输入与既有产物不变。真实数据验证仅在本机，不进入 CI。
2. **语言/资源**：中英文原始消息引用一致、不同翻译行数/清屏/区间内部入口等人工边界；目标文字、头像、图标和字形可追溯，拒绝缺失/损坏，不以消息块存在代替渲染正确。
3. **Core**：正常推进、等待前/截止时/晚到、一次输入的消费、显示完成回执、结束入口不清零、重复交互、默认上下文/颜色继承、无失焦冻结及未支持命令失败。预期来自参考与独立数据，不来自被测实现生成值。
4. **Godot 集成**：实际现代资源加载、真实输入到搜索/NPC 转向、对话暂停/继续/结束/再次交互和回到探索；按实际更新完成边界断言，不以测试协程耗时证明业务时序。
5. **图形与人工桌面**：真实 scene 4 与独立起点显示；头像、文字、字形/阴影、提示/调色板和背景恢复；Windows 键盘、翻页/加速、Alt-Tab 及正常关闭。明确它是独立验收模式，不以截图或 headless 证明其他场景行为。
6. **回归与 CI**：复用并最小扩展共享 `Test-M0.ps1`/runsettings 和人工 fixture；保留 Core/CLI/Prepare/Game、发现/重复、三个指定失败控制、import/Main 启动检查。按真实测试增量同步计数，不预填未来通过数。Windows CI 不上传真实内容，远端结果与本地/人工分开记录。

Godot/GdUnit/Prepare/solution 全局串行；运行前读 [测试异常说明](../../agents/test-diagnostics.md)，核当前脚本和 runsettings。已有 Godot 进程只查 PID/Name，确认归属前暂停；会话中止/崩溃/未知退出保留实际命令、提交、原日志与部分 TRX 后停止，不自动重试或升级工具链。成功必须核实际退出码、TRX Summary/RunInfo、完整性及指定控制原因，不能拼接历史部分结果。
